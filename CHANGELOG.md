# История изменений

Формат: [Keep a Changelog](https://keepachangelog.com/ru/1.1.0/). Версии: [SemVer](https://semver.org/lang/ru/)
(`MAJOR.MINOR.PATCH`). Все три платформы проверены на железе, используются версии `1.x`.

## [Не выпущено]

### Исправлено
- Windows: диск `RPI-RP2` не находился после перехода в режим загрузчика. Причина — поиск шёл только среди `DRIVE_REMOVABLE`, а RP2040 в BOOTSEL иногда определяется как `DRIVE_FIXED`. Теперь метка `RPI-RP2` ищется среди всех логических дисков, а метка тома читается с повторными попытками.
- Windows: после MSC-сеанса «мёртвый» COM-порт в списке принимался за живую плату, и программа ошибочно сообщала о чужой плате в BOOTSEL. Теперь `DeviceNotFoundError` при открытии порта повторяется, пока порт виден в списке, а проверка чужой платы выполняется только когда порт реально открывается.
- Windows: SD-карта Карабаса в режиме MSC теперь ищется среди дисков `DRIVE_FIXED` и `DRIVE_REMOVABLE` (RP2040 иногда определяется как `DRIVE_FIXED`), кроме системного диска и диска, на котором лежит сама программа. Запись на чужой диск дополнительно страхует `confirmDrive()`.
- Если порт Карабаса исчез, а диск `RPI-RP2` уже виден, прошивка продолжается без 1200-бод-сброса только после подтверждения пользователя: рядом может оказаться чужая RP2040-плата в BOOTSEL. Подтверждение запрашивается в обеих ветках (с MSC-сеансом и без него).
- Проверка «чужая плата в BOOTSEL» (`foreignBootloaderPresent`) теперь делает реальную пробу открытия порта, а не полагается на наличие порта в списке: после MSC-сеанса Windows может ещё показывать «мёртвый» COM-порт, и проверка давала ложное срабатывание.
- Если видно несколько дисков `RPI-RP2`, прошивка прерывается с просьбой отключить лишние RP2040-платы: подтверждение одного диска не гарантирует, что прошивка уйдёт на нужную плату.
- Порт считается исчезнувшим и при `DeviceNotFoundError` (порт в списке, но открыть его нельзя): после MSC-сеанса Windows ещё показывает «мёртвый» COM-порт, и вместо диалога подтверждения записи на `RPI-RP2` выводилась общая ошибка «Could not open the serial port».
- Журнал (`--log`) сохраняется рядом с исполняемым файлом программы; при недоступности каталога — в пользовательский каталог данных.
- Extra-контент копируется только при отмеченной галке «Download extra content»; маркер от прошлого запуска больше не приводит к копированию.
- Файлы из `extra.7z` копируются на SD-карту с заменой существующих; остальные файлы пользователя не трогаются.
- Перед копированием extra проверяется свободное место на SD-карте; при нехватке места копирование не начинается.
- Перед распаковкой `extra.7z` проверяется распакованный размер (лимит 2 ГБ).
- Симлинки из архива не копируются на SD-карту.
- В режиме «только extra» вызывается очистка служебных файлов ОС перед извлечением карты; сбой копирования теперь считается ошибкой, а не предупреждением.
- Windows: распаковка `extra.7z` падала с «Can not open the file as archive» / «Wrong password». Причина — `7za` при `-p` без значения читает пароль с консоли (`ReadConsole`), а не из stdin. Теперь пароль передаётся аргументом `-p<password>`.
- Диагностика ошибок `7za`: в журнал выводятся и stderr, и stdout (раньше — только stderr, а причина часто пишется в stdout).
- Содержимое `extra.7z` копируется в корень SD-карты без вложенной папки `extra/`, даже если архив содержит смешанную структуру (файлы в корне + папка `extra/`).
- Сравнение имён при бэкапе ядер теперь регистронезависимое: `ALF.KG3` на карте и `alf.kg3` в релизе считаются одним файлом.
- Устаревший маркер `extra_complete.txt` удаляется перед скачиванием, чтобы частично распакованный архив не был принят за готовый.
- Ошибки открытия/записи порта больше не маскируются под «нет ответа»: `sendMscCommand` возвращает `false` при `m_portOpenFailed`, `queryVersion` не повторяет попытки и не показывает диалог udev трижды, `resetPortToBootloader` прерывает прошивку при ошибке открытия.
- Если порт реально исчез и диск `RPI-RP2` уже виден, прошивка продолжается без 1200-бод-сброса — но только в ветке без MSC-сеанса. В ветке с MSC-сеансом операция прерывается с подсказкой, чтобы не прошить чужую RP2040-плату.
- `cleanupTemp()` не вызывает `removeRecursively()` при пустом `workDir()` (защита от удаления текущей папки процесса).
- `LC_ALL=C` применяется только к утилитам, чей вывод разбирается (`udisksctl`), а не ко всем дочерним процессам.
- Убрана несуществующая команда `cmake -E chmod` из POST_BUILD; права `+x` на `7za` выставляются через `file(CHMOD)` при конфигурации и дополнительно проверяются при запуске.
- Валидация UF2 усилена: проверяются `blockNo`, `payloadSize` (1–476) и family ID RP2040 во всех блоках.

### Изменено
- Архив `extra.7z` пересобран без дублирующей папки `extra/`.
- Архив дополнительного контента переведён с `extra.7z` на `extra.zip`; распаковка выполняется встроенной библиотекой `minizip-ng` (собирается через `FetchContent`), внешний `7za` больше не нужен.
- Сводка `Flash summary` печатается на всех выходах (включая сбой 1200-бод-сброса, отсутствие `RPI-RP2` и отмену) и показывает реальные статусы ядер и extra, а не наличие маркера.
- Распаковка `extra.zip` проверяет CRC (`mz_zip_reader_entry_close`), конец каталога (`MZ_END_OF_LIST`), фактически записанные байты и свободное место в кэше; имена с компонентом `..` отсекаются, а не по подстроке.
- `resetPortToBootloader` повторяет только временные ошибки (`OpenError`/`ResourceError`) и только пока порт виден в списке: сценарий «плата уже в BOOTSEL» больше не занимает 30 секунд.
- Разбор AT-ответов: `+KARABAS:` проверяется раньше `ERROR`, `ERROR` ищется без учёта регистра, дочитывающий цикл ограничен по времени и реагирует на отмену.

### Добавлено
- Автоопределение модели платы: кнопка с лупой рядом со списком моделей отправляет `AT+KARABAS=version` и по ответу `+KARABAS:<firmware>;<board>;<core id>;<core build>` выбирает нужную модель (1 — Karabas Go, 2 — Mini rev A-F, 3 — Mini rev G). Ответ выводится в журнал. Требует прошивку от 29.10.2026.
- Подтверждение записи на неопознанный диск: если на найденном томе есть файлы, но нет ядер `.kg1`/`.kg2`/`.kg3` и папки `backup_*`, программа показывает диалог с узлом, меткой, размером и списком файлов. Пустая карта принимается с предупреждением в журнале.
- Защита от чужой RP2040-платы в режиме загрузчика: если порт Карабаса ещё жив, а диск `RPI-RP2` уже виден, прошивка прерывается с просьбой отключить другую плату. Проверка выполняется в обеих ветках прошивки (с MSC-сеансом и без него).
- В журнал выводится размер найденного диска SD-карты и диска `RPI-RP2`.
- Лицензия MIT (`LICENSE`), сведения о сторонних компонентах (`THIRD_PARTY.md`); тексты лицензий входят в пакеты и сборки с Qt внутри.
- Пакет `.deb` для Ubuntu 24.04 и новее (на 22.04 в репозиториях нет Qt SerialPort - там AppImage): зависимости ставятся через `apt`, правило udev ставится автоматически, пункт меню.
- Понятное сообщение CMake со списком пакетов, если Qt 6 не найден.

- AppImage с Qt внутри (работает на большинстве дистрибутивов), в релизах на GitHub.
- `PKGBUILD` для Arch и Manjaro (`packaging/arch/git` и `packaging/arch/release`).
- Иконка приложения (`packaging/karabas-flasher.svg`).

### Изменено
- Добавлена галка «Update firmware» (включена по умолчанию), независимая от «Update cores» (раньше «Update core too»): можно скачать и прошить только прошивку, только ядра или и то и другое. При снятой галке поле выбора файла прошивки недоступно.
- README переписан для пользователей; информация для разработчиков перенесена в `docs/DEVELOPMENT.md`.
- Кнопка «SD Mode (MSC)» переименована в «Open SD card >», рядом добавлен значок «?» с подсказкой, что делает режим кард-ридера и как из него выйти. Кнопка теперь сама ждёт появления диска карты и открывает его в файловом менеджере системы.

### Исправлено
- Список портов показывает только USB-устройства на всех системах (раньше на macOS и Windows попадали Bluetooth-порты и порты по умолчанию выбирался первый из них).
- Запуск системных утилит (`udisksctl`, `gdbus`, `pkexec`) из AppImage: пути самого образа убираются из `LD_LIBRARY_PATH`.
- Windows: автоопределение модели (`AT+KARABAS=version`) не получало ответа. Причина — при открытии COM-порта не поднимались линии DTR/RTS, и USB-CDC устройство (RP2040) не передавало данные. Теперь линии поднимаются явно, ответ читается надёжнее (`bytesAvailable()` вместо результата `waitForReadyRead()`), а порт открывается по имени `COM3`, а не `\\.\COM3`.
- Windows: после перехода в режим MSC порт оставался в списке, и повторное нажатие «Open SD card >» отправляло команду MSC ещё раз. Теперь программа проверяет, не смонтирован ли уже диск Карабаса, и подсказывает, как выйти из режима.
- Определение диска Карабаса в режиме MSC больше не привязано к метке тома (`CORES`/`EXTRA`): проверяется содержимое — ядра `.kg1`/`.kg2`/`.kg3` в корне или папка `backup_*`. Так программа не путает Карабас со случайно вставленной флешкой.
- После прошивки больше не выполняется извлечение диска `RPI-RP2`: RP2040 перезагружается сам, а попытка извлечь уже исчезнувший диск давала ложную ошибку (Windows: «eject request failed (error 433)»).
- macOS: распаковка `extra.7z` больше не падает с «Wrong password» — пароль передаётся так, как ожидает `7za` на macOS.

### Проверено
- Ручное тестирование пройдено на Windows, macOS и Linux: скачивание прошивки и ядер, прошивка RP2040, обновление ядер на SD-карте, режим кард-ридера.

### Изменено
- Релиз для Linux теперь `.deb` вместо `.tar.gz` с голым бинарником (он не запускался без системного Qt нужной версии).

## [1.0.3] - 2026-10-28

Релиз посвящён безопасной работе с пользовательскими ядрами на SD-карте.

### Изменено
- В резервную папку `backup_...` переносятся только релизные ядра (те, что входят в набор с GitHub). Пользовательские и тестовые ядра, положенные на карту вручную, остаются на месте.

## [1.0.2] - 2026-10-28

Релиз посвящён исправлениям работы с дисками на macOS и ускорению монтирования.

### Исправлено
- macOS: убрано системное уведомление «disk not ejected properly» при извлечении SD-карты после обновления ядер.
- macOS: убрано такое же уведомление при извлечении диска `RPI-RP2` после прошивки; диск извлекается только если он ещё виден.
- macOS: `diskutil eject` выполняется без предварительного `unmount` (одна операция вместо двух).

### Изменено
- Монтирование раздела начинается почти сразу после его появления (300 мс вместо 2 с), при неудаче повторяется каждые 2 секунды. Ускоряет открытие SD-карты на Linux и macOS.

## [1.0.1] - 2026-10-28

Релиз посвящён поддержке второй карты памяти и мелким исправлениям.

### Добавлено
- Поддержка второй карты памяти (режим MSC 2, `AT+KARABAS=msc2`); переключатель 1/2 рядом с кнопкой «Open SD card >».

### Исправлено
- Команда MSC для первой карты: `AT+KARABAS=msc` (ранее ошибочно `AT+KARABAS=msc1`).
- Обновление ядер всегда выполняется через карту №1, независимо от выбранного режима MSC.
- Отмена, поданная до старта задачи, больше не теряется.
- Прошивка привязана к модели: при смене модели ранее выбранный файл сбрасывается.
- Порт не выбирается автоматически, если USB-портов больше одного.
- Усилена проверка UF2: family ID RP2040, число блоков и magic во всех блоках.
- При скачивании ядер выполняется одна повторная попытка при сетевом сбое.
- Перед копированием ядер проверяется свободное место на SD-карте.
- Иконка приложения для окна, Linux, Windows и macOS.

## [1.0.0] - 2026-10-27

Первый стабильный релиз: все три платформы проверены на железе.

## [0.1.0] - 2026-10-24

### Добавлено
- Первая кроссплатформенная версия на Qt 6: Linux, Windows, macOS (платформенный слой `Platform.h`).
- Скачивание прошивки и ядер с GitHub (ядра - по четыре параллельно), проверка формата UF2.
- Прошивка RP2040 через сброс 1200 bps и диск `RPI-RP2`.
- Обновление ядер на SD-карте: режим MSC, резервная копия `backup_...`, копирование с `fsync`, откат при ошибке, извлечение карты.
- Linux: установка правила udev через `pkexec` (`70-karabas-...rules`), извлечение карты через udisks `Drive.Eject`.
- macOS: очистка служебных файлов (`._*`, `.DS_Store` и др.) перед извлечением карты.
- Версия в заголовке окна, в журнале и по ключу `--version`; релизы на GitHub по тегам `vX.Y.Z`.
- Автоматическая сборка в GitHub Actions под три системы.
